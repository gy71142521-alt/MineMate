# explore_and_find 标准作业流程

执行入口为 `skill.py` 中的 `ExploreAndFind.execute()`，参数与契约来自 `metadata.py`。本文件描述程序现有流程，不是可由玩家或 LLM 改写后执行的脚本。

## 1. 受理与就绪检查

1. Skill Registry 校验名称和严格参数，执行器检查真实 Node 工具目录。
2. 复用共享执行槽，取得 Node 实例、代次和任务租约，启动心跳。
3. 通过 `/api/world` 读取快照，确认 Bot 可用；记录初始坐标和维度。
4. 更新阶段为 resolving。每次工具调用使用新的逻辑 operation_id，已提交的操作不因响应丢失而盲目重发。

## 2. 确认目标名称

调用 `resolve_resource(query=target, kind=target_kind)`，使用当前 Node registry 的真实名称。

- 无候选：返回 TARGET_UNKNOWN。
- 存在歧义：返回 TARGET_AMBIGUOUS。
- 两者都保留候选信息，阶段为 clarification_required；当前 HTTP Skill 不自动追问玩家。
- 唯一候选：进入搜索。

## 3. 本地搜索与候选复查

方块调用 `find_block`，实体调用 `find_entity`。搜索半径为 min(16, search_radius)，每次最多获取 16 个候选。

根据三维欧几里得距离再次过滤，目标须位于初始球形范围。排除无效实体，按距离排序，记录本次实际位置、候选数和截断状态。

最多尝试 6 个不同目标，以方块坐标或实体 ID 去重。每次尝试前再次调用对应搜索工具，确认原目标仍存在；前一个候选接近过程中位置可能已变化，不能沿用旧扫描。

- approach=false：确认目标后进入第 6 步。
- approach=true：进入对应接近分支。

## 4. 接近分支

### 方块

1. 已在 approach_distance 内时，先 `inspect_block` 检查名称和可见性，再复查原坐标；满足条件则跳过导航。
2. 否则调用 `find_interaction_positions`，半径 3、最多 6 个站位；优先接近目标的站位，最多尝试 3 个。
3. 调用 `goto_position(wait_seconds=0)`。若返回 pending，执行器通过 `get_movement_task` 有界查询原 taskId，禁止反复启动相同导航。
4. 导航完成后重新 `find_block` 确认同一坐标，检查真实三维距离，再 `inspect_block` 检查目标名称与可见性。
5. 明确失败可以尝试下一站位；目标丢失或没有可用站位则尝试其它候选。

### 实体

1. 已足够靠近时复查同一 ID，并按刷新后的位置核验距离。
2. 否则重新 `find_entity` 刷新位置，再调用 `goto_position`；pending 时查询原移动任务。
3. 到达后重新查找同一 ID、检查真实距离；未满足时最多再接近一次。
4. 不使用持续跟随，不攻击，不保证实体处于攻击视线；飞行、移动或隔墙目标可能无法完成接近。

## 5. 有限探索

只有当前搜索/接近未成功且 explore=true 时执行：

1. 以初始位置生成两圈四方向的有限水平路点，去重并限制 max_waypoints。
2. 导航终点须在初始搜索范围内；累计请求导航的直线段预算不超过 256 格。这不代表实际绕障路线长度受同样限制。
3. 调用 `goto_position`，等待原移动任务；明确失败也可能已部分移动，随后从实际停留位置重新搜索。
4. 重复第 3、4 步，直到找到目标或耗尽路点、目标尝试次数、调用预算或时间。

这是有限抽样探索，不扫描整个世界、不挖墙、不保证搜索整个球体。没有发现目标时不得断言世界不存在该资源。

## 6. 独立结果核验

执行后重新读取世界快照，依次检查四个完成条件：

| 条件 | 证据 |
| --- | --- |
| target_observed | 最新只读查询重新确认同一方块坐标/实体 ID |
| within_search_range | 目标到初始位置的三维距离不超过 search_radius |
| approach_verified | 未要求接近，或最终快照的 Bot 坐标与目标距离满足 approach_distance |
| same_dimension | 执行前、执行结果与最终快照维度一致 |

所有检查通过才能 completed。工具返回 completed 只表示该工具完成，不能替代上述验收。执行器最终释放对应旧租约，避免旧清理影响新任务。

## 7. 异常、取消与报告

- 导航明确失败、交互距离不足或区块不可读：只在代码允许的分支换站位/候选，次数有上限。
- 目标不存在：TARGET_NOT_FOUND；尝试过但无法接近或已丢失：TARGET_UNREACHABLE_OR_LOST。
- 最终检查失败：GOAL_NOT_VERIFIED，不标记成功。
- 工具调用预算耗尽、超时、Bot 断线/换维度、租约失效、执行取消：停止后续调用，保留实际进度和工具账本。
- 响应丢失时复用原请求回执；结果不确定即结束，禁止更换 ID 重发副作用。
- 用户可用游戏「停止」或 Skill cancel 接口取消；已发生的移动不回滚，不自动回到初始位置。

报告采用“请求目标 → 实际搜索/移动范围 → 找到的目标或失败原因 → 核验证据”。操作示例和对应工具顺序见 [SKILL.md](SKILL.md)。后续其它 Skill 也按“命令 → 工具调用顺序 → 成功验证方式”交付说明。
